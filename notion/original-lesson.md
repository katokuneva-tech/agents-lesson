## формула агента

$$
Агент = LLM (мышление) + Tools (действие) + Loop (настойчивость)
$$

> → мышление — способность рассуждать
> → действие — способность влиять на мир
> → настойчивость (и цикличность) — способность продолжать до результата

> *это не каноническая формула всех вендоров, скорее синтез того, из чего устроены реально разные агенты — от Claude Cowork до OpenClaw*

<details>
<summary>для сравнения</summary>

| источник | как описывают агента | насколько совпадает с формулой |
|---|---|---|
| **Anthropic** (Building Effective Agents, дек 2024) | Augmented LLM = LLM + retrieval + tools + memory. Агент = augmented LLM, динамически управляющий процессом и инструментами в цикле | LLM ✓ Tools ✓ Loop ✓ Memory как часть Tools |
| **OpenAI** (Practical Guide to Building Agents, 2025) | LLM управляет workflow execution, распознаёт завершение, самокорректируется, имеет доступ к инструментам | LLM ✓ Tools ✓ Loop ✓ |
| **MIT AI Agent Index** (2025) | четыре свойства: автономия, сложность целей, взаимодействие со средой, общность | Более высокоуровневое, но компоненты те же |
| **Andrew Ng** (2025) | четыре паттерна: Reflection, Tool Use, Planning, Multi-Agent Collaboration | Tools ✓ Loop (Reflection + Planning) ✓ |

## элемент агента – LLM (мышление)

что он может:
- понимать задачу на естественном языке
- найти подход к декомпозиции сложной цели на шаги
- выбрать, какой инструмент вызвать
- оценивать результат: получилось или нет?
- решать: продолжить, скорректировать или остановиться

[изображение: качество мозга = качество ризонинга по всем пяти типам. Если модель хорошо анализирует, но плохо рефлексирует, то цикл будет повторять ошибки]

## элемент агента: Tools (действия)

> Без инструментов модель — мозг в банке. Знает многое, но не может ничего сделать. Tools — это то, что позволяет агенту **действовать** в реальном мире, **менять среду**

**Технически это доступно благодаря:**
- **Function Calling / Tool Use** — стандартный механизм во всех ведущих API
- **MCP (Model Context Protocol)** — стандарт Anthropic (ноябрь 2024), ставший индустриальным

> **Пример из Claude Cowork / Claude Code:** имеет доступ к файловой системе (читать/писать/создавать), терминалу (выполнять команды). Все это — tools, которые модель вызывает самостоятельно

→ Не все задачи одинаково подходят для делегирования агенту. Как с живым ассистентом — что-то можно спокойно передать, а что-то лучше сделать самому. Гайд про фильтры для делегирования – на неделе.

### как концептуально понять Loop

Loop — это то, что превращает «один вопрос → один ответ» в «цель → автономная работа до результата». Агент создает и воспроизводит **структуру принятия решений**

**И ключевое свойство — цикличность,** повторение до достижения результата. В чате вы сами крутите этот цикл (даете обратную связь, добавляете вручную итерацию, задаете следующий вопрос, корректируете). В агенте модель крутит его автономно.

> Аналогия из менеджмента — цикл Деминга (PDCA).
> Агентный loop — это PDCA, только вместо человека его крутит модель

| PDCA | агентный loop | что происходит |
|---|---|---|
| Plan | Planning | Агент получает задачу, декомпозирует на шаги, выбирает инструмент |
| Do | Execution | Вызывает инструмент, исполняет действие |
| Check | Observation / Reflection | Смотрит на результат, оценивает прогресс |
| Act | Decision | Решает: продолжить, скорректировать план или завершить |

---

## циклы могут быть разные

- **короткий loop — 3-5 шагов**
  > *найди информацию и сделай отчет*
- **длинный loop — десятки шагов**
  > *перепиши модуль кода, протестируй, исправь баги*
- **непрерывный loop — бесконечно, пока запущен**
  > *любой мониторинг и проактивные действия*

> каждый луп может быть запущен нами (ставим задачу агенту), расписанием (задачи по cron — Claude Cowork внедрил пару недель назад), внешним тригером (для этого можно использовать n8n, в Cursor также появились автоматизации с начала марта)
>
> ***Чем длиннее loop → больше автономности → больше пользы → но и больше риска***

## Skill.md

Скилл — маркдаун-файл, который агент использует как инструкцию для выполнения задачи. Вы можете заложить в инструкцию:
- как технически должна решаться задача — какой порядок, стандарты или формат
- *по какой методологии* должна решаться задача — какие критерии суждения и чья профессиональная оптика должна применяться

> Пример: Наталья Рейслер разбирает 50 откликов на HH. У Натальи есть критерии, red flags, понимание, что важно для этой вакансии. Без скилла агент рассортирует резюме по формальным признакам. Со скиллом, в который Наталья упаковала свои критерии, агент будет оценивать как Наталья. Экспертиза одна, но масштаб 50 резюме вместо 10

→ на этой неделе подумайте: какая ваша повторяющаяся задача заслуживает скилла? Та, где у вас есть методология, которую вы хотите масштабировать
